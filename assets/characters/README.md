# 人物美术资源

人物美术统一走 `CharacterAssetResolver`。当前四名主角和三种敌军职业都已经提供正式原创统一图集；只有正式素材确实缺失或校验失败时，才会回退到程序绘制人物。

## 当前已完成的正式图集

| 素材键 | 游戏角色/职业 | 主色 |
| --- | --- | --- |
| `adrian` | 亚德里安 | 深蓝 |
| `celine` | 塞琳 | 深蓝 |
| `rowan` | 罗文 | 深蓝 |
| `mira` | 米拉 | 深蓝 |
| `raider` | 掠夺者 | 粉红 |
| `guard` | 守卫 | 粉红 |
| `captain` | 队长/桥头队长职业回退 | 粉红 |

当前分支不再使用旧的单文件 `sheet.png` 或 `sheet.b64`。此前大文件在仓库写入链路中出现过截断，导致 Godot 报 `ERR_FILE_CORRUPT` / PNG CRC 错误，因此已经清理。

正式图集现在使用经过逐段校验的 Base64 文本分段：

```text
assets/characters/<key>/
├── sheet.0.b64
├── sheet.1.b64
└── sheet.2.b64
```

如果某个主片段仍然较大，可以继续拆成四个子片段，例如：

```text
assets/characters/<key>/
├── sheet.0.b64
├── sheet.1.b64
├── sheet.2.0.b64
├── sheet.2.1.b64
├── sheet.2.2.b64
└── sheet.2.3.b64
```

`EmbeddedCharacterArtCatalog` 会优先读取子片段；没有子片段时读取对应主片段。三个主区域全部拼接完成后才解码 PNG，并且必须通过 `512×576` 尺寸检查。游戏不会联网，也不会在运行时生成角色内容。

## 统一图集规格

每套正式图集严格为 `512×576 px`。

图集区域：

- 头像：左上角 `64×64`
- 地图人物：`32×32` 固定格，从 `y=64` 开始
- 战斗人物：`96×96` 固定格，从 `x=112` 开始

地图方向顺序固定为：

1. `down`
2. `left`
3. `right`
4. `up`

地图帧：

- `Idle`：每方向 2 帧
- `Walk`：每方向 3 帧

战斗帧：

- `Idle`：2 帧
- `Attack`：4 帧
- `Cast`：4 帧
- `Hit`：2 帧
- `Dodge`：2 帧
- `Defeat`：3 帧

右侧战斗人物由游戏自动水平镜像，不需要再制作一套反方向帧。

## 战斗画面基准

正式 `96×96` 战斗帧按 4× 绘制，再由战斗人物控件整体使用 `0.75×`，最终得到严格的 3× 逻辑像素显示。角色脚底统一校准到战斗状态框的 `y=305` 上沿，相关位置从 `ReferenceBattleLayout` 读取。

物理攻击时间线约为 `0.34s`，施法蓄力约为 `0.50s`。人物动作只表现已经由战斗规则结算出的结果，不重新计算命中或伤害。

## 查找优先级

每个候选素材键按以下顺序寻找：

1. 人物/实例 ID，例如 `adrian`、`celine`、`mira`
2. 职业 ID，例如 `raider`、`guard`、`captain`
3. 阵营默认目录：`player_default` / `enemy_default`

因此塞琳会直接命中 `celine` 正式图集；普通掠夺者即使战场实例 ID 被改成 `enemy_01`，仍会通过职业 ID `raider` 命中正式敌军图集。桥头队长同样会通过职业 ID `captain` 使用队长图集。

## 旧独立素材兼容

项目仍支持针对单个角色/动作明确覆盖的独立素材：

```text
assets/characters/<key>/
├── map.png
├── portrait.png
├── battle.png
├── map/
│   ├── idle_down_0.png
│   └── ...
└── battle/
    ├── idle_0.png
    ├── attack_0.png
    └── ...
```

独立序列帧编号必须从 `0` 连续递增。遇到第一张缺失编号后，解析器会把此前的连续文件视为完整动画。

## 原创边界

角色比例、职业轮廓、盔甲层级、披风结构和战斗姿态保持统一的古典日式战棋视觉语言；脸、发型、装备细节、武器造型、徽记和角色身份均使用本项目原创设计，不直接复制商业游戏正式角色素材。
